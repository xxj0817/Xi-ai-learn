# 规格增量：联网知识检索（知识库扩展）

## ADDED Requirements

### Requirement: 知识库检索作为研究工具

当请求指定了知识库文档范围且用户已登录时，系统 SHALL 把一个知识库检索工具与现有 Tavily 工具一起提供给研究 Agent，由 Agent 自主决定本次任务查私有知识库、联网搜索，还是两者兼用。系统 MUST NOT 用固定规则替 Agent 决定只用其中一个数据源。

#### Scenario: Agent 只查私有知识库

- **WHEN** 用户的私有文档足以回答该问题，且 Agent 判断不需要联网
- **THEN** 研究结果只包含知识库来源，题库主题与题目依据私有文档内容

#### Scenario: Agent 两者兼用

- **WHEN** Agent 判断既需要私有资料也需要外部背景
- **THEN** 研究结果同时包含知识库来源与网页来源，并统一编号

#### Scenario: 未指定知识库范围

- **WHEN** 请求没有指定 `knowledge_doc_ids`
- **THEN** 工具集与行为与引入知识库之前保持一致，仅包含 Tavily 工具

### Requirement: 知识库检索的确定性兜底

当知识库工具已提供给 Agent，但 Agent 未调用它、调用失败，或当前配置无法运行 Agent（如离线 Mock）时，系统 MUST 至少执行一次基于用户输入的知识库检索，保证私有资料不被静默跳过。

#### Scenario: Agent 未调用知识库工具

- **WHEN** Agent 结束研究但没有产生任何可核实来源
- **THEN** 系统补一次知识库检索，并把命中的私有分块作为来源继续出题

#### Scenario: 离线 Mock 模式下的知识库

- **WHEN** 当前模型提供方为 mock（无法运行研究 Agent）但用户已指定知识库文档
- **THEN** 系统仍完成知识库检索并基于其内容出题

### Requirement: 知识库来源与网页来源统一编号

知识库分块命中后 SHALL 与网页结果进入同一套来源归一化流程：按确定性顺序排序、限制总数量、统一编号 `S1..Sn`，并把来源类型标记为知识库。

#### Scenario: 混合来源编号

- **WHEN** 一次研究同时命中知识库分块与网页结果
- **THEN** 两类来源合并在同一个列表里连续编号，每条来源的类型字段能区分是知识库还是网页

#### Scenario: 知识库分块去重

- **WHEN** 同一分块在多次工具调用中被重复命中
- **THEN** 最终来源列表里只保留一条该分块

### Requirement: 知识库范围隔离研究缓存

研究结果缓存的键 MUST 包含知识库文档范围。文档范围不同的两次请求 MUST NOT 复用同一份缓存结果。

#### Scenario: 不同文档集不共享缓存

- **WHEN** 两次请求的用户输入、地区与用户资料完全相同，但指定的知识库文档不同
- **THEN** 第二次请求重新执行研究，不复用第一次的缓存结果

#### Scenario: 相同范围命中缓存

- **WHEN** 两次请求的输入、地区、用户资料与知识库范围完全一致且缓存未过期
- **THEN** 第二次请求直接复用缓存，不再调用任何检索工具
